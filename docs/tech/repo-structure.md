## 1. Top-Level Layout

```
karjat-farms/
├── index.html                  # HTML5 prototype (reference only — not shipped in Unity build)
├── sprites3/                   # Pixel art assets (reference — Phase 1 Sprites import)
├── groundwork-unity/           # Unity 2022.3 LTS project (Phase 1+)
├── docs/                       # All documentation (source of truth)
├── supabase/                   # Migrations, Edge Functions, RLS policies (Phase 2+)
├── scripts/                    # Dev/ops scripts (mandi scrapers, data generators)
├── tests/                      # Unit/integration tests (Python + Unity PlayMode)
├── .gitignore                  # Excludes (see §5)
├── README.md                    # Links to docs/README.md, Phase 0 status
└── LICENSE
```

**Rule:** Unity build artifacts (.apk, .aab) are never committed — CI generates and stores them.

## 2. Unity Project Layout (`groundwork-unity/`)

```
groundwork-unity/
├── Assets/
│   ├── KarjatData/            # ScriptableObjects + JSON data (CROPS, seasons, prices)
│   ├── Scenes/                # One scene per game phase
│   ├── Prefabs/               # Tile, crop, UI prefabs
│   ├── Scripts/               # Game logic (FarmingEngine, CropManager, Market)
│   ├── UI/                    # Canvas prefabs, HUD elements
│   ├── Audio/                 # SFX + music stubs
│   └── FarmingEngine/         # Purchased asset integration layer
├── ProjectSettings/
├── Packages/
├── .vscode/                   # Unity debugger config (gitignored locally)
└── groundwork-unity.sln       # .NET solution
```

**Farming Engine import:** Asset store package goes into `Assets/FarmingEngine/`. All Karjat-specific overrides live in `Assets/Scripts/` — never modify the `FarmingEngine/` folder directly (preserve upgrade path).

## 4. Prototype Assets (`index.html`, `sprites3/`)

- **index.html**: fully playable HTML5 prototype. Kept as design reference. **Never ported into Unity as-is.** Used for:
  - Game feel validation
  - CROPS object extraction (source of truth for Phase 0 data)
  - Loop prototyping before Unity integration
- **sprites3/**: pixel art source files. Unity sprites imported as individual PNGs from this folder at Phase 1 start.

**Pixel art PNGs are committed** (sprites3/). All other large binaries use Git LFS.

## 6. Branch Strategy

```
main                        # Stable — Claude SA merges PRs here after audit
├── docs/phase0-p0          # Phase 0 documentation (Moraen writes; PM opens PR)
├── feature/phase1-*        # Phase 1 Unity integration
├── feature/phase2-*        # Phase 2 Supabase backend
└── hotfix/*                # Emergency fixes
```

**Rules:**
- `main` is always deployable
- Feature branches cut from `main`
- PRs require SA audit before merge (Phase 0+)
- **`docs/phase0-p0` → `main`:** Cursor PM opens PR from **moraen-Home**; **Claude SA audits and merges** (2026-06-05 rule). Trainee answers product questions; does not merge by default.
